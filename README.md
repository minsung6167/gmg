# GMG (가면가)

지도 위에서 랜덤으로 지목된 국내 지역을 기준으로 주변 관광지·축제·행사 정보를 제공하고, 사용자가 고른 장소로 맞춤형 여행 일정을 생성하는 서비스. "가면 가지"에서 착안한, 즉흥적이고 계획 없이 떠나는 여행 컨셉.

- 팀: 노플랜(No Plan) — 최민영, 최민성, 원재민
- 과목: 캡스톤디자인 (컴퓨터공학과 3학년 2학기)
- 1차 버전 범위: 국내 여행

## 기술 스택

| 구분 | 기술 |
| --- | --- |
| 백엔드 | Spring Boot (JDK 25 / Corretto) |
| 프론트엔드 | React + Vite (Node 24) |
| DB | MySQL |
| 지도 | 카카오맵 API, 카카오모빌리티 Directions, 카카오 대중교통 길찾기 |
| 관광 데이터 | 한국관광공사 TourAPI |
| 평점/리뷰 | 네이버 검색 API + Jsoup 크롤링 → DB 캐싱 |
| AI 일정 생성 | Google Gemini Flash |

## 폴더 구조

```
gmg/
├── back/   # Spring Boot 백엔드
└── front/  # React + Vite 프론트엔드
```

## 실행 방법

**백엔드**
```
cd back
# application-local.properties.example → application-local.properties 복사 후 Gemini/TourAPI 키 입력
./mvnw spring-boot:run   # http://localhost:8080
```

**프론트엔드**
```
cd front
# .env.example → .env 복사 후 카카오맵 JS 키 입력
npm install
npm run dev
```

백/프론트는 별도 포트로 동작하므로 개발 시 둘 다 실행해야 하며, CORS 허용 설정이 필요합니다. `application-local.properties`, `.env`는 절대 커밋하지 않습니다.

## 핵심 설계 원칙 (1차 버전, 절대 준수)

1. 거리/방문순서는 LLM이 아닌 카카오 API 실측 + 알고리즘으로 결정
2. Gemini는 확정된 데이터를 바탕으로 슬롯(점심/저녁/자유시간) 배치와 이유 문구만 생성 — 순서는 바꾸지 않음
3. 식당/상호명 등 실존 고유명사 추천 금지 — 카테고리 슬롯만 배치(할루시네이션 방지)
4. 체류시간은 AI가 추정하지 않음(최초 0분, 사용자 입력) — 이후 재계산은 AI 재호출 없이 산술로만 처리(이동시간은 최초 계산값 재사용)
5. 네이버 평점 크롤링 결과는 DB(`place_rating`) 캐싱, 실시간 재크롤링 금지
6. TourAPI cat1/cat2/cat3 코드는 하드코딩 금지, `categoryCode` API로 최신값 확인
7. 모든 외부 API(TourAPI/카카오/네이버/Gemini) 실패·timeout에 대한 예외처리(재시도/안내) 필수
8. 결측/빈값(null/empty) 처리 철저
9. 자차 유무에 따라 이동시간 API 분기 (자차: 카카오모빌리티 Directions / 대중교통: 카카오 길찾기, 단 직선거리 1km 미만은 API 호출 없이 도보시간 추정 — 거리(km)/4×60분)
10. 비밀번호는 1차 버전에서 평문 저장/비교(암호화 없음, 발표 시 한계점으로 명시), 인증은 `HttpSession`에 `user_id` 저장
11. `user_id`가 필요한 기능(즐겨찾기 등)은 세션 기반 식별, 비로그인 접근 시 로그인 화면으로 리다이렉트 — 랜덤 추천/지도 조회는 비로그인도 가능
12. 1차 버전은 사후검증(재검토 로직 등) 생략 — 발표에 "향후 개선"으로 명시
13. "다시받기" 버튼은 (a) 이미 AI 일정표 생성됨(`filters.status = 계획 완료`) AND (b) 그 이후 필터가 1개라도 변경됨, 두 조건을 모두 만족할 때만 노출

## 서비스 흐름

로그인(세션, 비로그인은 즐겨찾기 전까지 가능) → 지역 랜덤 선정(테마 선택 시 테마 관광지가 있는 지역만 후보) → TourAPI로 인근 관광지 최대 20곳 조회 → 네이버+Jsoup 평점 보강/캐싱 → Top3 추출 → 카카오맵 표시 → 즐겨찾기 저장(로그인 필요) → 여행일수 기준 k-means 클러스터링 → 이동시간 매트릭스 계산(자차/대중교통 분기) → AI(Gemini) 일정 JSON 생성 → 체류시간 입력 시 캐스케이드 재계산 → 필터 변경 시 "다시받기"

### 필터 조건 (사용자 입력)

인원수, 여행 날짜(시작/종료 → 일수 자동 계산 → k-means의 k), 동반자 유형(다중선택: 어린이/부모님/친구/애인 등), 테마(산/바다/도시/시골, TourAPI cat 코드 매핑), 자차 이용 여부. 체류시간은 필터가 아니라 일정표 화면에서 입력.

## 화면 구성

| 화면 | 내용 |
| --- | --- |
| 0. 로그인/회원가입 | 세션 인증, 즐겨찾기부터 로그인 강제 |
| 1. 첫 화면 | 필터 + 카카오맵 + 랜덤 여행지 추천 |
| 2-A. 홈 | 확정 지역 정보, 가볼만한곳 리스트, 즐겨찾기 |
| 2-B. 계획(생성 전) | 즐겨찾기 리스트, AI 계획 짜기 버튼 |
| 2-C. 계획(생성 후) | 일자별 탭, 클러스터링 지도, 체류시간 입력 |
